Bot Bastion 3D: camera, picking and readability
One fixed-tilt camera, a few cheap modes, and overlays that keep range rings, nodes and lanes readable. All maths is pure Kotlin (see SPEC section 3). Frames use the same sprites and projection as the in-game board.
Default tilt, 50 deg

Plan view, 90 deg
True perspective (R2): FOV 38, orbit
Ray-pick placement: finger -> ground plane -> nearest node
Placement ghost: snapped to node 7, ring previews range, haptic tick on snap
Picking rules (JVM-tested)
1. Unproject the touch to the ground plane (z = 0).
2. Bots: ray against the bounding cylinder, nearest depth wins, bots beat nodes.
3. Else nearest node within max(0.55 u, 28 dp), ties by screen distance then id.
4. 56 dp Voronoi hit regions where nodes are closer than 56 dp (40 dp on phones).
5. Lane or void taps do nothing and announce a hint (TalkBack polite).
No mesh raycasts are needed: nodes are fixed points on a plane.

Co-op and one camera
One camera, one pick pipeline for all players.
Two players on the same side of a tablet: tilt is fine.
Tabletop (players face each other) or 3 to 4 players: Plan view is forced, so nobody sees the arena upside down. R1 reuses the 2D top-down art; no extra bake.
Reduced Motion removes camera moves and shake only.
